# Achroma 0.1.0

First standalone palette and Stylus release. The operator confirmed browser visual
acceptance of the verified candidate and authorized publication after successful
final-commit CI and release-artifact verification. See
[release readiness](https://github.com/noidilin/achroma/blob/main/docs/release-readiness.md)
for evidence and the release procedure.

## Scope and fidelity

- Standalone dark/light palettes (66 keys each) and offline Stylus UserCSS
  generation, without dotfiles, chezmoi, mise, a browser, or network at build time.
  Python 3.11+ is required; the tested runtimes are listed below.
- 132 styles from the locked 134-style Catppuccin snapshot. Codeberg and
  PythonAnywhere are excluded because their precompiled dependencies have
  hardcoded colors. Reimport does **not** remove existing copies of those styles.
- No palette values, selectors, exclusions, upstream snapshot bytes, saved
  settings, flavor defaults, or accent defaults changed from the extracted
  baseline. Upstream names, namespaces, enabled flags, inclusions and site
  variables are preserved. Achroma Light uses Latte and Dark uses Mocha;
  Catppuccin Frappé and Macchiato remain unchanged. Default accent is `rosewater`.
- The standalone export bundles supported dependencies and removes upstream
  update URLs and stale compiled sections/digests. There are no runtime Less/CSS
  imports; external website images/fonts may still require network. This is not
  an upstream refresh or a selector redesign.
- The generated native files remain byte-identical to the independently approved
  extraction candidate. The legacy hosted `lib/lib.less` is a separate frozen
  asset; neither its bytes nor the existing Pages deployment is changed here.

## Portable defaults, explicit custom fitting

The new versioned `applications/stylus/filters.lock.json` is a canonical derived
build input, not a cache. It binds all 52 resolved colors and their approved
coefficients to the complete resolved-palette digest. Normal builds validate it
and fail closed on missing, stale or invalid locks; they never silently fit
coefficients. This preserves reviewed default native bytes across the tested
macOS/Linux platforms despite an inherited platform-libm difference in the fitter.
Input hashes/report fingerprints change to account for the lock, not native colors
or styles.

Custom source experiments must explicitly opt into `--fit-custom-colors` and use
a distinct local candidate. The seeded fitter is **not guaranteed bitwise portable**;
numerical tolerance does not prove equivalent browser rendering. Palette/role
changes require a separately reviewed lock refresh before becoming defaults.
See [customization and refresh](https://github.com/noidilin/achroma/blob/main/docs/stylus.md). Never substitute a customized
rebuild for verified public release bytes.

## Archive and compatibility contract

The release assets are `achroma-0.1.0.zip`, external `SHA256SUMS`, and workflow
`SOURCE.json` identifying the full checked-out source revision. The ZIP contains:

- `manifest.json`
- `palette/{dark,light}.json`
- `mappings/stylus/{dark,light}.json`
- `themes/stylus/{import.json,lib.less}`
- `fragments/stylus/{dark,light}.less`
- `data/consumer.json`
- `reports/stylus-build.json`
- `licenses/*`

Manifest and consumer contract `schemaVersion` is **1**. Consumer data has exactly
`schemaVersion`, `release`, `palettes`, and `mappings`; release identity carries
`version` and a full 40-character `sourceRevision`. Palettes/mappings agree with
their individual files. Manifest input and payload maps use relative POSIX paths
and SHA-256 hashes. The consumer object embeds no archive URL/checksum; consumers
supply a trusted pin externally. See [the consumer contract](https://github.com/noidilin/achroma/blob/main/docs/consumption.md)
and [archive verification](https://github.com/noidilin/achroma/blob/main/docs/release.md#archive-contract).

The ZIP is reproducible for the same inputs/version/revision, with sorted regular
members and fixed metadata. `SHA256SUMS` covers the ZIP including its manifest;
the manifest hashes all payload files other than itself. Integrity hashes are not
an independent authenticity source. Verify trusted provenance before use.
The Less fragments are variable declarations only, not complete stylesheets or
replacements for the helper library.

`v0.1.0` maps to producer version `0.1.0`; semantic prereleases are supported,
but build metadata and leading-zero numeric identifiers are not. Before 1.0,
incompatible schema/path changes require a minor version; from 1.0 onward they
require a major version. Color and upstream changes must be explicit in notes.
No minimum Stylus extension version has been established by browser testing.

## Import, reimport and rollback cautions

**Importing sets Stylus's global `updateInterval = 0`, affecting unrelated
installed styles as well.** This is not a per-style setting. Export a live Stylus
backup before any import and record the prior update policy.

Manually import `themes/stylus/import.json` only into an isolated profile first.
Review enabled states, document scopes, chosen accent and site variables,
dark/light transitions, and the retained Frappé/Macchiato paths. Test reimport
and the retention of excluded styles explicitly; disable existing excluded copies
manually if desired. Reimport is not a clean uninstall or rollback. Main-profile
import needs separate approval. Rollback means restoring the live backup and
checking global settings and unrelated styles, not reverting repository files.
There is no automatic installation, activation, OS switching, or browser import.

## Validation and platform limits

- Hosted Ubuntu 24.04 x64, Python **3.13.13**, Node **22.17.1**: successful
  [merged-source CI](https://github.com/noidilin/achroma/actions/runs/42379529378)
  at `09b67d712135f3b37677cad68a1ea7918d7ed606`. All **60 Python tests**,
  **132 styles × 2 flavor paths / 310 document sections**, archive verification,
  plain Python consumer and isolated reproducibility passed. Validation ran in
  a fresh Linux network namespace after locked online dependency preparation.
- macOS, Python **3.13.13** / Node **22.17.1**: full local repair validation passed.
  Independent local review also passed with Python **3.15.2** / Node **26.13.0**.
- Existing Colima Linux arm64, Python **3.12.3**: 60 tests, default build,
  verification and consumer passed offline; native bytes matched macOS. No Node
  compiler execution occurred in that VM. See [validation history](https://github.com/noidilin/achroma/blob/main/docs/validation.md).
- Windows execution is untested. Declared Python 3.11+ support is not a claim that
  every supported Python/platform combination was executed.
- **Browser visual acceptance: operator-confirmed.** The operator tested the
  verified import prepared from `9b015dfaf7ab7279c8a0ef72c34cc9f1a24563ba` and
  reported that everything looked good. Its `import.json` SHA-256 is
  `84cb4b1cfba2cb41076c8e2984cd254feded67b36a26b982e2e40db7ae7615b1`.
  Browser/OS/Stylus versions and individual reimport, excluded-style retention,
  global-policy and backup-restore results were not supplied; those checks are
  not claimed as independently verified. This is visual acceptance, not complete
  per-site or cross-browser coverage. Compiler success is separate evidence.

Publication requires successful CI on the exact final notes-bearing commit and
verification of the tag-build artifacts against that commit and the browser-tested
native hashes. Neither earlier merged-source CI nor operator visual acceptance
substitutes for those automated identity and integrity checks.
